# Run 历史与持续会话分开显示

状态：方案草案，待 Claude 评审。2026-10-30。

## 1. 问题与已确认的方向

用户发现：打开旧 run，看到的似乎是当前 active session，历史记录像是变成了同一份。

当前代码可以解释这个现象：

- S1 让会话属于工作区。同一个主导可以先后参与多个 run，继续使用原会话及上下文。
- `apps/gui/src/views/Run.tsx` 直接以 `run.planner` 打开 `SessionView`。
- `SessionView` 调用 `useSession(name)`，读取 agent 的完整 transcript，并持续折入该 agent 的实时事件，没有 run 范围。
- `TranscriptTurn` 和 `AgentInput` 当前没有明确的 run 归属字段。
- `crates/mock-agent/tests/session_reuse.rs` 已有同一主导在 run B 恢复 run A 会话的测试。这是预期的上下文延续能力，应保留。

以上是代码层面的诊断，尚未检查用户实际数据库，不能据此断言历史数据完整或被覆盖。

已与用户确认：采用「会话继续复用，每个 run 有独立历史视图」。只改变本地记录与展示，不因页面筛选而裁剪模型上下文。每个 run 新建会话、用摘要承接，不作为本次默认方案。

## 2. 用户看到的行为

### Run 页

- 默认「仅本次 run」，展示该 run 的消息、任务、交接和结果。
- 进行中的 run 持续更新；完成、取消等终态的 run 为只读历史，隐藏发送、中断当前 agent、切换模型等实时会话操作。
- 提供「打开完整会话」入口，跳到独立的 session 页面。不要在旧 run 的标题下悄悄变成操作当前 session 的界面。
- 旧 run 的状态来自 run，自身已经结束时，不应因为主导正在 run B 工作就显示为运行中。
- 主导的当前状态如需展示，明确写成「Pia 当前正在 Run B」，作为独立链接，不冒充 run A 的历史状态。
- 费用、上下文用量、错误、模型信息不能直接把 session 当前值标成本次 run 的值。无法计算的本次指标先不显示；确需展示完整会话指标时明确标注范围。
- 「继续这项工作」后续可创建新 run 并保存来源关系；本期不必扩展新建流程，至少不能通过旧 run 页直接给当前 session 发消息。

### Session 页

- 保留完整对话和现有会话操作。
- 在消息归属发生变化处显示 run 标题与链接；同一 run 多次出现可重复标记，不假设其消息一定连续。
- 普通聊天、无法确定归属的历史分别标识，不能一律挂到当前 active run。
- 用户从这里向正在参与 run 的 agent 发消息时，显示本次发送的目标范围。

例：A 实现登录功能，B 接着补测试，二者由同一个 Pia session 执行。打开 A 只见 A；打开 B 只见 B；完整会话可见 A、B 及中间的普通聊天。模型仍可使用原先已经拥有的上下文。

## 3. 数据归属：以消息为单位，入队时固定

建议给本地消息信封、输入事件和 transcript turn 增加归属元数据。字段命名由实施者结合现有类型确定，但必须表达三种情况：

| 归属 | 含义 |
| --- | --- |
| run | 明确属于某个 `run_id`，必要时带 `task_id` |
| chat | 明确属于普通聊天 |
| unknown | 旧数据缺字段或证据不足 |

不能只用一个可空 `run_id` 混合表达普通聊天和未知历史。可以采用带标签的 `scope` 枚举，旧事件缺字段默认 `unknown`。

归属规则：

1. 编排器发出的 kickoff、任务通知、评审、继续执行等，携带明确的 run/task 来源。
2. Run 页发消息携带目标 run；服务端校验该 run、agent 关系及发送是否仍允许。终态 run 不接受新的用户输入。
3. Session 页发消息时，服务端在接受消息时根据明确目标或当时有效占用确定范围。若页面展示的目标与接受时的占用不符，返回明确错误供刷新重试，不静默改发另一个 run。
4. 内部延迟通知以产生通知的原始 run 为准，不能用投递时的当前 claim 覆盖来源。跨 run 通知聚合必须分桶，不能把 A、B 消息合成一个仅有单一归属的 turn。
5. 入队后的归属不随 agent 换 run、重启、消息更新或开始执行而改变。队列持久化和恢复路径必须保存该元数据。
6. 校验目标、确定归属和入队之间要避免占用切换竞态；沿用现有锁或事务机制，不能先读 claim 再无保护地异步发送。

`reply_to`、`thread` 表示消息关系，不能直接当作 run 归属；跨 run 回复也可能存在。

输出、工具调用和 diff 归属其 turn。先审计现有输出如何绑定正在执行的消息，只有现有绑定不足时再补关联字段，不必把 `run_id` 无差别复制到所有事件。

## 4. API 与前端实现建议

第一版优先复用完整 transcript 的折叠逻辑，再从中派生 run 视图：

- `Envelope` → 队列/恢复 → `AgentInput` → Rust `Fold` → `TranscriptTurn` → GUI 实时折叠，全链路保留归属。
- `useSession` 继续维护完整会话；给 Run 页提供明确的 `runId` 范围，在完整折叠结果上过滤 turn。
- 不要先丢弃其他 run 的实时事件再调用现有 `applyEvent`。当前部分输出按 active turn 折叠，提前过滤可能把 B 的输出错误接到 A 的最后一个 turn。
- `last_seq` 仍是事件同步游标，不是 run 的结束边界。重连、刷新后的结果必须与连续接收实时事件一致。
- 页面范围必须进入相关状态/缓存的身份；同一个 planner 的 A、B 之间切换时，不能保留旧的草稿、选中项、报错或异步响应。
- `SessionView` 不宜只增加一个 turn filter 就结束。需要审计 composer、outbox、questions、handoff、工具栏、侧栏、错误、usage 等所有依赖完整 session 的子组件。
- 区分实时 session 状态与历史 turn 状态；只有属于当前 run 的问答、操作和交接出现在 run 页。
- 可先不增加单独的 transcript API。历史量大时再引入服务端范围查询/分页，但须保持相同归属规则。
- 更新生成的 TypeScript bindings、序列化兼容测试，并按仓库现有规则决定 API 版本是否需要变化。

「已结束」不要求冻结一份重复的整段 transcript。终态之后，已被接受的原有 turn 可能仍有尾部输出、工具结果或状态修正，应继续归入原 run。禁止的是新输入混入、其他 run 内容混入；不要用结束时间截断一个尚未完整落盘的 turn。

## 5. 旧历史兼容

不重写原始事件，不删除历史，不按当前 active session 批量重绑旧记录。

旧数据默认 `unknown`。先调查现有事件中是否有能精确关联 `message_id` 与 run 的来源证据，再决定是否做独立、可重建的归属索引。

- 明确的消息引用或执行关系可用于回填，记录推断来源。
- 只有时间落在 run 起止区间内，或「这个 agent 曾担任 planner」，不足以自动认定归属。区间内可能有普通聊天和排队消息。
- 若只有近似依据，本期宁可不自动归属，也不要把估计当作确定历史。
- 旧 run 没有可确认的消息时，显示「这次运行的历史尚未分组」，提供完整会话入口；不要显示成「从未有过消息」。任务和结果仍按已有 run 数据显示。
- 删除 run 后，保留 S1 的会话生命周期行为；完整会话内相关消息不能消失。归属 ID 不级联删除消息，标题可回退为「已删除的运行」。

本期可以只保证新消息精确分组、旧消息安全展示。历史回填可以独立实施，不能作为上线新归属记录的前置条件。

## 6. 上下文与缓存约束

本次改动只影响 CrossAgents 本地元数据和读模型：

- 保留原来的厂商 session/thread 恢复流程。
- run 归属不拼进 prompt，不插入模型可见的历史分隔符，不重写已有消息。
- 页面上的「仅本次 run」不传入模型请求组装逻辑，不导致历史裁剪、摘要或新开 session。
- 不因这次改动改变模型、系统提示、工具定义、消息顺序或已有 cwd 切换策略。

验收目标是「相同业务操作下，新增归属信息不改变驱动侧请求语义」，不是承诺每次缓存必定命中。缓存还有过期、模型与请求前缀变化等外部因素；同一 session ID 本身不是命中保证。

新建独立会话的选择可以另做；它会改变上下文延续方式，不纳入本次修复。

## 8. 验收场景

- A 完成后同一个 Pia 启动 B：A 不出现 B 的消息、实时状态、错误或费用；完整会话包含二者。
- 在 A、B、完整会话之间快速切换并制造请求乱序：不会显示错误范围、串草稿或串操作目标。
- B 正在流式输出，用户查看 A：B 的输出不会追加到 A 最后一轮；重连/刷新后结果一致。
- A 消息排队后占用变化，或 hub 重启恢复：消息仍属于原先接受时的范围，不改挂 B。
- A 的延迟通知遇到 B 当前占用：保留 A 来源；聚合器不合并不同归属。
- 用户在旧 run 页无法向当前 session 发新消息；从 session 页发送遇到目标变化时不能静默改发。
- 普通聊天和无归属旧事件保持可见，未知历史不会伪装成空历史或自动划入当前 run。
- 一个 run 在时间线上出现多段消息、终态后有尾部结果：按归属完整展示，不靠单一时间窗裁剪。
- 删除 A 不删除 Pia 对话、不影响 B，历史链接正常降级。
- 保留现有 session reuse 测试，并在驱动边界比较相同输入操作的请求：新增本地 scope 不进入 prompt，不新开厂商会话，不改变原请求内容与顺序。
