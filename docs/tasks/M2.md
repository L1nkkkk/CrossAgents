> 依据：[DESIGN.md](../DESIGN.md) §7–§9 · 状态：已完成 · 2026-10-21

> M2（协作层 + 验收）与 M3（固定 Pipeline）互相依赖，合并实现。

## 1. 目标

```
crossagents agent add arch  --plugin claude --model opus  --role planner --cwd ~/proj
crossagents agent add coder --plugin claude --model haiku --role worker  --cwd ~/proj
crossagents run "给项目加用户登录" --planner arch --worker coder
crossagents run show <id>            # 看 Planner 拆出的计划
crossagents run approve <id>         # 批准后自动派发、验收、合并
crossagents run show <id>            # 跟踪每个任务的状态
git merge crossagents/<run>          # 结果在集成分支上，由人决定是否合入
```

## 2. 设计决定

| 决定 | 原因 |
|---|---|
| **工具逻辑全部在 hub**：`GET /v1/me/tools` 按角色返回工具定义，`POST /v1/me/tools/{name}` 执行 | MCP server 只是一层薄代理；以后 GUI、其他协议也能复用同一套工具（DESIGN §2 原则） |
| **`crossagents mcp`**：stdio MCP server，自写最小 MCP（initialize / tools/list / tools/call），复用 `drivers::jsonrpc` | 与 ACP 同理，不绑定 SDK |
| **每个 agent 会话一个令牌**，hub 内存保存，经环境变量交给 MCP server | 工具调用能可靠识别调用者；会话结束令牌失效 |
| **编排在 `crates/orchestrator`**，只依赖 core；通过 `AgentHost` trait 使用 hub 的 runtime | 依赖只朝内（DESIGN §2） |
| **集成分支**：每个 Run 建 `crossagents/<run>` 分支（独立 worktree），任务分支从它派生、验收后合并回它 | 不碰用户当前的工作区；最终是否合入由人决定 |
| **Worker = 模板 agent 的临时克隆**：同插件/模型，cwd 指向任务 worktree，任务结束即删除 | 每任务新会话（DESIGN §4.1） |
| **验收由 hub 执行**：Worker 调 `task_complete` 后在任务 worktree 里逐条跑 `acceptance` 命令 | 不信 Worker 自述（DESIGN §8） |
| **失败处理**：附输出打回同一 Worker；超过 `max_attempts` 后若有 `--escalate` 模板则换更强的 Worker 在同一 worktree 重做，否则失败并通知 Planner | DESIGN §8 Retry |
| **Worker 结束回合却没调工具**：自动提醒，最多 2 次，之后按失败处理 | 弱模型常见问题 |
| **并发与冲突**：默认最多 3 个并行；两个任务的 `scope.allow` 前缀重叠（或任一为空）则不并行 | DESIGN §7 |
| **runs / tasks 表改为「索引列 + JSON data 列」**（迁移 0002 重建两张空表） | 结构还会演进，避免频繁迁移 |
| **mock agent 支持指令**：`[write 路径=内容]`、`[call 工具 {json}]`、`@N` 只在第 N 次尝试生效 | 不依赖 LLM 跑完整条流水线 |

## 3. 工具

| 工具 | 角色 | 说明 |
|---|---|---|
| `agent_list` | 全部 | 列出 agent |
| `agent_send(to, text)` | 全部 | 给 agent 发消息 |
| `plan_submit(tasks)` | planner | 提交计划：`[{key, title, spec, depends_on}]`；校验后进入审批 |
| `task_list()` / `task_status(task_id)` | planner | 查看任务 |
| `task_read(task_id)` | planner | 完整报告：总结、验收输出、diff 统计 |
| `task_answer(task_id, answer)` | planner | 回答 Worker 的提问 |
| `task_complete(task_id, summary)` | worker | 交付；触发验收 |
| `task_fail(task_id, reason)` | worker | 放弃；触发升级或失败 |
| `task_ask(task_id, question)` | worker | 向 Planner 提问 |

## 4. 验收

- 端到端（mock agent，无 LLM）：Planner 提交两个有依赖的任务 → 审批 → Worker 写文件 →
  一个任务第一次验收失败、重试后通过 → 两个任务合并到集成分支 → Run 完成，分支上有两次合并提交
- 拒绝计划、取消 Run、Worker 提问/Planner 回答、升级到更强模板、结束回合未交付的提醒，各有测试
