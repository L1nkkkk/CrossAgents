# M5 任务书：Agent 账号管理（先接 Codex）

> 依据：[DESIGN.md](../DESIGN.md) §5、§6 · 状态：后端与 CLI 已完成；GUI 待 Electron 改造合并后做 · 2026-10-21

## 1. 目标

把「登记一个 agent」升级为**账号管理**：引导式接入、看得到订阅等级、实时额度、余额、
token 消耗与缓存命中，支持多个账号并让每个 agent 绑定其中一个。先做 Codex，接口按多家设计。

```
crossagents setup codex                  # 引导：环境 → 账号 → 登录 → 状态 → 模型 → 建 agent → 试连
crossagents account ls
crossagents account status codex-main    # 套餐、额度窗口与重置时间、余额（实时）
crossagents account usage codex-main --by day|model|agent   # token、缓存命中
crossagents account add codex --label work   # 第二个账号（独立 CODEX_HOME）
crossagents account login work           # 打开浏览器登录
crossagents agent add coder --plugin codex --account work --model gpt-5.6-luna --role worker
```

## 2. 已确认的数据来源（2026-10-21 实测）

| 数据 | 来源 |
|---|---|
| 登录方式、套餐、订阅到期 | `<CODEX_HOME>/auth.json`：`auth_mode`；`id_token` 声明里的 `chatgpt_plan_type`、`chatgpt_subscription_active_until` |
| 实时额度、余额 | `GET https://chatgpt.com/backend-api/wham/usage`（`Authorization: Bearer <access_token>`、`ChatGPT-Account-Id`）：`plan_type`、`rate_limit.primary_window/secondary_window`（已用 %、窗口长度、重置时间）、`credits` |
| token 消耗、缓存命中 | `<CODEX_HOME>/sessions/**/rollout-*.jsonl`：`session_meta`（`id`、`originator`、`cwd`）、`turn_context.model`、`event_msg/token_count.info.total_token_usage`（`input_tokens`、`cached_input_tokens`、`output_tokens`、`reasoning_output_tokens`），以及额度快照 `rate_limits` |
| 可用模型 | ACP `session/new` 的 model 选项；`models_cache.json` |

`originator == "crossagents"` 的会话由 CrossAgents 发起，`session_meta.id` 与 ACP 会话 id 一致，
因此可以把用量精确归到 agent、角色和 run。

## 3. 设计决定

| 决定 | 原因 |
|---|---|
| **账号（Account）是一等概念**：`id`、`provider`、`label`、`home`（该账号的 `CODEX_HOME`） | 多账号 = 多个独立 home；agent 通过 `config.account` 绑定，插件启动时设置 `CODEX_HOME` |
| 默认账号就是现有的 `~/.codex`（setup 时导入），新账号放在 `<crossagents home>/accounts/<id>/` | 不打扰已有的 Codex 使用；新账号彼此隔离 |
| **新扩展点 `AccountProvider`**（core）：`status`、`usage`、`login_command`、`env` | 以后接 Claude 等其他家只需各写一个实现，API、CLI 和 GUI 都不用改 |
| **令牌只在 hub 进程内使用**，API 与事件永远不返回令牌；邮箱打码显示 | 安全；GUI 和日志都看不到凭据 |
| 实时额度优先，失败（无网、令牌过期）时回退到会话日志里的最近快照，并标明数据来源与时间 | 总有数据可看，也不会把旧数据当成实时 |
| **不自己刷新令牌**；令牌过期时提示重新登录或运行任意 Codex 会话（codex 自己会刷新并写回） | 避免与 codex 同时刷新导致 refresh token 失效 |
| 实时结果缓存 60 秒；会话日志按文件修改时间增量扫描 | 不频繁请求、不重复解析 |
| 登录：hub 以账号的 `CODEX_HOME` 运行 `npx -y @openai/codex login`，把它输出的登录链接转给客户端，完成后发 `account.login_completed` 事件 | 走官方登录流程，CrossAgents 不碰密码 |
| 用量接口的基础 URL 可配置 | 测试时指向本地假服务器，不依赖真实账号 |

## 4. 验收

- 假的 `CODEX_HOME` 测试夹具（auth.json + 会话日志）+ 本地假用量服务：状态、额度、余额、
  按天/模型/agent 的 token 与缓存命中都正确；令牌过期时回退到快照；API 输出中不含令牌
- agent 绑定账号后，启动的 Codex 进程带正确的 `CODEX_HOME`
- 在本机真实账号上：`account status` 显示实时套餐与额度，`account usage` 显示历史 token 与缓存命中
- GUI 部分（账号页、引导向导）在 Electron 改造合并后做
