# N3 任务书：claude-native 驱动

> 前序：[N1](N1.md)（codex-native）· [N2](N2.md)（原生数据进界面）· 调研：[claude-stream-json.md](../research/claude-stream-json.md) · 状态：完成（Claude Code 2.1.304 上实测） · 2026-10-22

## 1. 问题

Claude 之前只能走 ACP 适配器（`claude-agent-acp`，要 Node.js）。这条路拿不到额度，工具详情要从 ACP 的内容里拼，也做不了恢复、分叉和换模型。调研发现 Agent SDK 只是 `claude -p` stream-json 控制协议的封装，所以 hub 可以用 Rust 直接说这套协议。

## 2. 改动

| 层 | 内容 |
|---|---|
| 驱动（`drivers/claude_native`） | 一个会话一个 `claude -p --input-format stream-json --output-format stream-json --permission-prompt-tool stdio` 进程。会话 id（`--session-id`）和每条用户消息的 uuid 都由 hub 指定，用户消息 uuid 就是轮次 id。支持：流式文本与思考（`--include-partial-messages`）、工具调用、权限回调（`can_use_tool` 转给 hub 的权限流程）、中断、挂起与恢复（`--resume`）、分叉（`--fork-session --resume-session-at <该轮最后一条助手消息>`）、换模型与 effort（`set_model`、`apply_flag_settings`）、压缩（`/compact`） |
| 翻译（`wire.rs`） | 工具标题与类别（shell / 编辑 / 读 / 搜索 / MCP / 子 agent）；`tool_use_result` 的结构化结果直接填 `ToolDetail`：shell 的 stdout/stderr 与退出码，编辑的 `structuredPatch` 转统一 diff，新建文件转全 `+` diff，MCP 等工具的参数和结果；用量（上下文占用取每轮最后一次请求，花费取进程累计值的差）；`rate_limit_event` 与 `get_usage` 转 `RateLimits`（五小时、每周、按模型的周限额、额外用量、套餐）；子 agent 的内部步骤不展开 |
| 隔离 | 默认 `--setting-sources project,local` 和 `--strict-mcp-config`：不带用户自己的 Claude Code 插件、hook、连接器，只挂 hub 的 MCP。agent 的 `config` 可写 `setting_sources`、`permission_mode`、`effort` |
| 账号（`plugins/claude_account.rs`） | provider `claude`：一个账号一个配置目录（`CLAUDE_CONFIG_DIR`；默认目录 `~/.claude` 不设这个变量，因为它的 `.claude.json` 在目录外）。登录状态来自 `claude auth status`；套餐、额度和模型来自一个不开会话的 `claude` 进程（`initialize` + `get_usage`），每个账号最多一分钟问一次；token 用量扫描 `projects/*/*.jsonl` 转写（同一条回复只算最后一行）。hub 启动时登记本机已登录的 `~/.claude` |
| 来源 | 驱动设置 `CLAUDE_CODE_ENTRYPOINT=crossagents`，用量页「按来源」能把 CrossAgents 的会话和用户自己用 Claude Code 分开 |
| 代理 | `claude` 不读 Windows 系统代理。hub 环境里没有 `HTTPS_PROXY` 等变量时，从注册表读系统代理，设 `HTTPS_PROXY` / `HTTP_PROXY`；两种来源都会补 `NO_PROXY` 放行本机地址（与已有的 `NO_PROXY` 合并），否则 agent 里的 `crossagents mcp` 连 hub 也会被代理吃掉。拉起会话（以及 codebuddy 的探测）之前先对这个代理做一次 TCP 连接测试（2 秒），连不上就直接报错并点名代理地址，而不是让 agent 起来之后卡在发不出请求上。`crossagents` CLI 自己连 hub 的客户端固定 127.0.0.1，显式 `no_proxy` |
| 找 `claude` | PATH 上的 `claude`；`~/.local/bin/claude`（原生安装）；Claude 桌面版自带的最新一份（`%LOCALAPPDATA%\Claude-Data\…\claude-code\<版本>\<构建>\claude.exe`） |
| 插件 | `claude` 默认驱动改为 `claude-native`；`driver = "acp-generic"` 仍可改回 ACP 适配器；`native_command` 可指定 `claude` 路径 |

## 3. 验收

- `cargo test --workspace`、clippy、fmt 通过。新增单元测试：启动参数、流式文本不重复、工具详情（shell 退出码、编辑 diff、新建文件、MCP）、每轮用量与花费、停止原因、权限请求与回答、额度翻译、控制消息、转写扫描、账号环境变量、系统代理解析、代理地址解析与端口探测。
- 冒烟测试 `crates/drivers/tests/claude_smoke.rs`（`--ignored`，真实 Claude Code，haiku）4 项全过：一轮里建文件并带 diff、用量、额度；`Deny` 策略下写文件被拒、文件没建；中断后 `Cancelled`；分叉后的会话只记得分叉点之前，挂起后新进程恢复并换模型、记得之后的对话。
- 真实 hub + GUI：自动登记「本机 Claude 登录」；新建 Claude agent（haiku）用 hub 的 MCP 工具列出队友、改 README、跑 `git diff --stat`，会话里能展开编辑的 diff；用量页显示 Pro 套餐、5 小时 33%、每周 67%、使用中的 @cleo，token 用量按天、按来源（crossagents 与其他）都有，可用模型来自 Claude Code。

## 4. 没做

- 回退（rollback）：`rewind_files` 能撤销文件，但回退对话历史要换会话 id（分叉），而 `DriverSession::session_id` 是固定的；等 hub 有回退入口时一起做。
- 一个进程一个会话；每个 Claude agent 常驻一个 `claude` 进程。
- macOS / Linux 的系统代理没读（那边通常已有 `HTTPS_PROXY`）。
- 账号的「额外用量」只在开启时显示，还没在开启的账号上实测过。
