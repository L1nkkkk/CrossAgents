# R1：结束后的 run 能再开 Work，能删除

状态：A、B 已完成。

## 1. 起因

2026-10-26 Pia 想为「Git 视图」开一个新 Work，被 hub 拒绝："you lead run 01a17773… already"。那个 run 已经 `completed`。同时 GUI 里一个停在 `planning` 的旧 run（`01a17769`）没法删。

## 2. 问题 A：已结束 run 的主导不能再开 Work

### 2.1 现状

- `work_start`（`crates/orchestrator/src/work.rs`）只要调用者当过任何 run 的 planner 就拒绝，不看状态。
- `lead_run`（`team.rs`）要求 run 未结束。两边标准不一致，结束后的主导两头都走不通。
- 只把判断改成 `!r.status.is_terminal()` 不够：`create_run` 用 planner 的 `cwd` 当 `repo`、用它当前分支当 `base_branch`。主导住在旧 run 的集成工作区（Pia 的 cwd 是 `~/.crossagents/worktrees/9bdcd23c/integration`），新 run 就会以旧集成工作区为仓库、以 `crossagents/9bdcd23c` 为基线，落地也落回旧 run 分支，而不是 `main`。
- 从首页新建 Work 时选 Pia 当主导，也有同样的问题。

### 2.2 改法

1. `work_start` 的拦截只看未结束的 run：`r.planner == caller.id && !r.status.is_terminal()`。
2. `NewRun` 加两个可选字段 `repo: Option<PathBuf>`、`base_branch: Option<String>`，`create_run` 优先用它们，缺省时才回退到 planner 的 cwd 和当前分支。
3. 新增 `Orchestrator::home_of(agent)`：如果 agent 的 cwd 等于某个 run 的 `integration_path`，就返回该 run 的 `(repo, base_branch)`，否则返回 `(cwd, None)`。`work_decided` 和 `POST /v1/runs`（首页新建）都通过它确定仓库和基线。
4. 旧 run 已结束但没落地（`landed == None`）时，卡片 `detail` 末尾加一句提示："上一个 run 还没落地，新 Work 从 `main` 开始，不包含它的改动。" 不自动把旧分支并进来，由人决定。

### 2.3 测试（`crates/mock-agent/tests/work_start.rs`）

- 主导所在的 run 结束后再发起 Work：可以出卡片；点「开始」后，新 run 的 `repo` 是原仓库，`base_branch == "main"`，新主导的 cwd 在新 run 的集成工作区里。
- 主导所在的 run 未结束：仍然被拒，文案不变。
- 首页以旧主导为 planner 新建 run：`repo` 和基线同上。

## 3. 问题 B：run 不能删除

### 3.1 现状

- hub 的 run 接口只有查看、approve、reject、cancel、land、finish、diff、trace，没有删除；`Store` 也没有 `delete_run`。
- 一个 run 关联的东西：`runs` 行、`tasks` 行（外键 `ON DELETE CASCADE`）、`run_id` 指向它的 human items 和 notes、事件、集成工作区和任务工作区、`<worktrees>/<run>/target` 构建目录、`crossagents/<short>` 和 `crossagents/<short>-<task>` 分支、主导的副本 agent、这个 run 招募的 agent（`spawned_by_run`）。

### 3.2 决定

- 只能删除已结束的 run（completed / failed / cancelled）。未结束的返回 409 "cancel it first"。GUI 把两步合成「取消并删除」。
- 硬删除，不做归档。run 不像对话需要回头接着聊，结束后留着只占侧边栏；真要回看，有分支和事件可查。以后如果觉得需要「恢复」，再仿照对话加 `archived_at`。
- 事件不删：事件日志只追加，`seq` 要连续，trace 和 agent 历史也依赖它。GUI 遇到 `run_id` 已不存在的事件就不显示 run 链接。
- 分支默认保留，原因是未落地的改动只存在于分支上。
  - 已落地（`landed.is_some()`）：分支默认一起删。
  - 未落地：只有带 `branches=true` 时才删，GUI 的复选框写明"未落地的改动会丢失"。
- 集成工作区里有未提交改动、且 run 未落地时，不带 `force=true` 一律 409，并列出改动文件。
- 主导副本和招募来的 agent 一并移除（先打断当前轮次）。确认框写明"和 X 的对话会一起删除"。发起这个 Work 的原对话不受影响。

### 3.3 各层改动

- core：`Store::delete_run(id)`，默认实现返回 `Unsupported`；新增事件 `EventKind::RunDeleted { run_id }`。
- store-sqlite：在一个事务里删 `human_items`、`notes`（按 `run_id`）、`tasks`、`runs`。`tasks` 不依赖 CASCADE（连接上不一定开着 `foreign_keys`），显式删除。
- orchestrator：`Orchestrator::delete_run(id, DeleteRun { branches, force })`，持 run 锁，按以下顺序执行，各步失败只记 warn、继续往下（与 `cancel` 一致），最后才删库：
  1. 校验状态和脏工作区；
  2. 打断并移除主导副本和招募的 agent（`host.remove_agent`）；
  3. 移除剩余任务工作区（`cleanup_worktree`，按需带分支）；
  4. 移除集成工作区和构建目录（`remove_integration`），按需 `git branch -D` run 分支；
  5. `store.delete_run`，然后发布 `RunDeleted`。

  返回一个列出实际清理项的清单（agents、worktrees、branches、warnings）。
- hub：`DELETE /v1/runs/{key}?branches=&force=`，`api-types` 新增 `DeleteRunResponse`，ts 类型重新生成。
- cli：`crossagents run rm <run> [--branches] [--force]`。
- GUI：
  - Run 页标题栏：已结束的 run 显示「删除」，未结束的显示「取消并删除」。
  - 侧边栏 run 项右键加「删除」。
  - 确认框列出主导名、工作区、分支和落地状态，分支复选框的默认值按 3.2 走；有脏改动时列出文件，并提供「仍然删除」。
  - 收到 `RunDeleted` 后从列表移除；当前正在看的 run 被删时跳回首页。
  - `MockBridge` 补上对应数据，供截图检查。

### 3.4 测试

- store：删 run 后，tasks、human items、notes 都没了；删不存在的 run 返回 NotFound。
- mock-agent（新文件 `tests/delete_run.rs`）：
  - 未结束的 run 返回 409；cancel 之后可以删。
  - 已落地的 run：工作区、分支、主导副本都消失，`/v1/runs` 里不再有它，收到 `RunDeleted`。
  - 未落地的 run：默认保留分支；带 `branches=true` 时分支消失。
  - 集成工作区有脏改动：不带 `force` 返回 409 并列出文件，带 `force` 能删。
  - 发起 Work 的原对话 agent 仍在。
- GUI：`tsc --noEmit` 通过；mock 数据下截图检查确认框。
