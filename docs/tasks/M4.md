| 项 | 内容 |

## 2. 设计决定

| 决定 | 原因 |
|---|---|
| **插件协议 = ACP**，不再另定义 CrossAgents Plugin Protocol | M1 已证明 ACP 足以表达统一 Agent 接口；外部插件只需讲 ACP，生态里现成的适配器直接可用 |
| 清单字段：`name`、`protocol = "acp"`、`command`、`models`、`model_env` | 与 `config.toml` 的 `[plugins.<name>]` 相同，只多了协议声明 |
| `command[0]` 是相对路径（含 `/` 或 `\`）时相对插件目录解析 | 插件可以自带可执行文件或脚本 |
| 清单有误时跳过并记录警告，不阻止 hub 启动 | 一个坏插件不影响其他 agent |
| 优先级：内置 < 插件目录 < `config.toml` | 用户配置最终说了算 |
| **成本从事件日志计算**，不另建写入路径 | ACP 稳定版只上报会话累计成本（`usage_update.cost`）与上下文占用；事件里已有全部信息，按需聚合即可 |
| 会话成本取该会话最后一次上报值，会话以 `agent.status_changed → starting` 分界 | 上报值是会话累计值 |
| Worker 的成本归属其任务所在的 run；Planner 归属它最近领导的 run | 足够回答「这个 run 花了多少、强弱模型各花多少」 |

## 3. 验收

- 插件目录里的 mock 插件能被 `plugin ls` 列出并跑通一轮对话
- `usage --by role` 在跑完一个 run 后分别列出 planner 与 worker 的成本
- CLI 全流程（`agent add` → `run` → `run show` → `run approve` → 完成）对 mock agent 通过
