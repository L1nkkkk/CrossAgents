# N2 任务书：原生驱动采到的数据全部送到界面

> 前序：[N1](N1.md)（codex-native）· [V4](V4-GUI.md) · 状态：完成（codex-cli 0.163.0-alpha.11 上实测） · 2026-10-22

## 1. 问题

codex-native 能采到的信息，大约一半在 hub 这一层被丢掉，GUI 用到的更少。具体有：命令输出与退出码、文件改动内容、MCP 调用的参数和结果、整轮 diff、额度、权限请求、警告（都被当成错误显示）、分项 token；另外，hub 重启 agent 时总是新开会话，没有用上驱动本来就支持的恢复。

## 2. 改动

| 层 | 内容 |
|---|---|
| 驱动（`codex_native/wire.rs`） | `item/commandExecution/outputDelta` 翻译为 `ToolOutput`；`item/completed`（文件改动在 `item/started` 就带）翻译为 `ToolDetail`，包括命令、工作目录、退出码、耗时、输出、文件改动及其 diff、MCP 参数、结果和错误；命令标题改用 `commandActions`，不再显示 `powershell.exe -Command '…'` 这层包装 |
| 核心类型 | `ToolDetail`、`FileChange`；`TokenUsage`、`RateLimits`、`PermissionDecision` 改为可序列化，并导出 TS 类型 |
| hub 事件 | 新增 `agent.tool_output`（合并后发布，每个调用最多 64 KB）、`agent.tool_detail`（输出保留末尾 32 KB）、`agent.turn_diff`、`agent.permission`、`agent.rate_limits`、`agent.warning`、`account.quota_updated`；`agent.usage` 增加 `tokens` |
| transcript | 工具调用带 `output` / `detail`；新增 `permission`、`warning` 条目；每轮带 `diff`；用量带 `tokens` |
| 恢复会话 | 驱动支持恢复时，runtime 先用该 agent 上次的 vendor session id（`Store::last_session_id`）恢复；失败则发一条警告并新开会话 |
| 账号 | hub 启动时把已登录的 vendor 本机登录（`~/.codex`）登记为账号（`[accounts] detect`，默认开启，测试里关闭）；没指定账号的 agent 归到这个账号；agent 上报的额度按账号缓存，比 provider 的数据新时覆盖，有变化时发 `account.quota_updated` |
| API | `GET /v1/quota`：所有账号的状态、模型，以及正在使用该账号的 agent；`POST /v1/agents/{key}/compact`：压缩上下文 |
| GUI · 会话 | 工具步骤可以展开，显示命令、工作目录、输出（最近 400 行）、退出码和耗时、文件 diff、MCP 参数和结果；运行中的命令在下方实时显示最后 4 行；失败的命令标出「退出 N」；授权作为步骤折叠；警告用琥珀色；轮尾显示「改动 N 个文件 +a −b ▸」，展开看 diff；上下文条悬停显示累计 token 分项；上下文用到一半以上时出现「压缩上下文」 |
| GUI · 用量 | 参照 Claude Code 的用量设置页：每个账号一块，包括服务、套餐、邮箱；每个限额窗口一行，显示名称、重置时间、进度条和「N% 已用」（75% 起琥珀色，90% 起红色）；额外额度；数据来源与更新时间；使用中的 agent。可以展开按天、模型、agent、来源查看 token 和缓存命中，以及可用模型；还能添加账号（新登录或导入本机登录）、重新登录、移除。页面下半部分是原来的「CrossAgents 里的花费」 |
| GUI · 侧栏 | 底部显示用得最多的那个窗口，例如「额度 8% · 30 天」，点击进入用量页 |
| 补充 · 限额 | 每轮结束后驱动调用 `account/rateLimits/read`，读出 `rateLimitsByLimitId` 的所有限额组（主限额在前）和限额重置券；hub 按限额 id 合并单次上报和完整读取的结果；`AccountStatus` 增加 `limits`、`reset_credits`；用量页在主限额之后按组显示「某模型 的限额」，并显示「额度重置券 · N 张可用 · 最早 M月D日过期」 |
| 补充 · ACP | `tool_call` / `tool_call_update` 翻译为 `ToolDetail`：文本内容作为输出，`diff` 项生成统一 diff（按行 LCS），`rawInput` 作为参数（shell 的 `command` 单独取出），`rawOutput` 作为结果。Claude 经 ACP 的工具步骤也能展开 |
| Electron | `http(s)` 链接（例如登录页）在系统浏览器里打开 |

额度展示与 vendor 无关：任何 provider 只要给出 `AccountStatus`（窗口、重置时间、额外额度、套餐），就按同一套样式显示。以后接入其他订阅，只需新增一个 `AccountProvider`。

## 3. 验收

- `cargo test --workspace`、clippy、fmt 通过。新增测试：wire 对命令输出与结果、MCP 详情、文件改动的翻译；transcript 对输出、详情、警告、diff 的折叠；GUI 纯函数 `lib/diff.ts`、`lib/quota.ts`。
- 用真实 Codex 走过：
  - 用量页自动出现「本机 Codex 登录」，显示 Free 套餐、30 天限额 8%、额外额度余额、使用中的 @ada 和 @coder，以及按天的 token 和缓存命中率。
  - hub 重启多次后，coder 仍然记得之前的对话（会话恢复）。
  - 一轮里 `git log`、编辑 README、`git show nope` 三步都能看到输出；失败命令显示「退出 1」，展开能看到 fatal 信息和工作目录；轮尾「改动 1 个文件 +1 −0」展开后是 README 的 diff。

## 4. 没做

- 分叉、回退（fork / rollback）还没有 API 和界面入口。
