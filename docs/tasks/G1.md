# G1 任务书：工作组是持续的工作空间，run 是其中一轮

> 依据：2026-10-29 讨论（人老是在 Work 里让 AI 再开一个 Work；结束的 run 不能接着干，新 Work 要跳到另一个页面，历史也被切成几段）· 状态：方向已定，未开工 · 2026-10-29

## 1. 目标与边界

人看到的是**一个持续存在的工作组**：一段连续的对话，配一个主导。一轮任务做完，直接在同一个对话里说下一个目标，同一个工作组接着干，不新开 Work，也不跳页面。各轮的目标、结果和状态在右侧查看。

- **底层每一轮仍是一个 run。** 落地、检查、总结、花费、删除都按 run 算，这些逻辑不动。不做“把已结束的 run 原地重开”：那样 completed、landed 的含义会变得模糊，相关的每一处都得重写。
- “原地改目标”说的是体验：同一个对话、同一个页面、同一个主导会话，底层换一个新 run。
- **只有人主动新建 Work**（首页，或在会话里同意 `work_start` 的提议）时，才另开一个独立的工作组。
- 不做：一个工作组同时跑两轮；同一个工作组中途换主导（要换主导就新建 Work，见 §3.5）。

## 2. 现状（已核对代码）

| 位置 | 现在 | 和目标的差距 |
|---|---|---|
| `protocol.rs` LEAD 末尾 | “The person may keep talking to you after the run is closed; answer, but start no new work in a closed run.” | 结束后只能回答，不能接着干 |
| `work.rs` `work_start` | 已结束 run 的主导可以再提一个 Work（R1-A），人在卡片上点开始后，建一个全新的 run | 绕一圈：先提议、再确认、再跳到新页面 |
| `work.rs:131` | 旧 run 没落地时，新 Work 从 `main` 开始，卡片会提示“不含上一个 run 的改动” | 接着干的场景，一般应该在上一轮的改动上继续 |
| `Run.tsx` `RunView` | run 页就是主导的会话（`SessionView key={run.planner}`），上面是 run 的信息，下面是收尾和参与者，旁边是任务板 | 对话本来就是连续的（S1 之后主导是会话本人），缺的是“轮”这一层 |
| `Sidebar.tsx` | 工作区分组里，run 和会话按时间平铺，每个 run 一行 | 同一组的各轮会散成好几行 |
| `panes.ts` | 右侧工具列有 改动 / 任务 / 事件流 / 提交图 | 没有“各轮”的列表 |
| `core::Run` | 没有“属于哪个工作组”这样的字段 | 需要新增 |

## 3. 设计

### 3.1 数据

- 新表 `works`：`id`、`title`（按话题起名，可以改名）、`repo`、`lead`（主导会话的 AgentId）、`created_at`、`updated_at`。
- `Run` 加 `work_id`。迁移时，已有的每个 run 各自成为一个工作组，标题沿用 run 的标题。
- 一个工作组同时最多有一个未结束的 run，在建新一轮时检查，并加锁。
- 事件：`WorkCreated`、`WorkUpdated`（改名、换了当前轮）。`RunCreated` 带上 `work_id`。

### 3.2 怎么开始下一轮

上一轮结束后，人在这个工作组的对话里发消息，消息照常交给主导。由**主导判断**这是新目标还是在问上一轮的事：

- 新目标：主导调用新工具 `run_next`（参数：`title`、`request` 写人的原话、可选的 `from`，见 §3.3），hub 当场在同一个工作组里建新 run，不出卡片。人在这个工作组里提出需求，本身就是授权；计划要不要审批，照这一组的策略走。
- 问题、闲聊、对上一轮的追问：直接回答，不开新一轮。

不在 hub 里猜“这句话算不算新任务”，交给模型判断（见记忆“hub 是给模型用的”）。GUI 在已结束的轮次下面，把输入框的提示换成“说下一个目标，就在这里开始下一轮”。

人也可以不经过主导直接开：右侧“各轮”窗格顶部有个“下一轮”按钮，等于 `POST /v1/works/{id}/runs`。

### 3.3 分支：默认叠在上一轮上

| 上一轮 | 新一轮从哪里开始 | 落地 |
|---|---|---|
| 已落地 | 更新后的基线分支 | 照常 |
| 已结束，没落地，分支上有改动（completed / failed） | **上一轮的 run 分支**，即接着它的改动干 | 落地新一轮时，上一轮的改动一起进基线；上一轮记为 `landed`，`by` 写“随第 N 轮落地” |
| 取消了，或者分支上没有改动 | 基线分支 | 照常 |

`run_next` 的 `from: "base"` 可以改成从基线开始（新目标和上一轮毫无关系时用）。这时上一轮没落地的改动留在它自己的分支上，各轮窗格里标出“未落地”。

`run_land` 在新一轮叠在没落地的上一轮上时，落地说明里要列出连带落地的轮次。人从 run 页单独落地上一轮，也照常可以；之后新一轮再同步一次基线。

### 3.4 主导会话

- 主导就是工作组的那个会话本人（S1 §3.2）。每轮开始时把它放进新一轮的集成工作区（`place`），这一轮结束后送回工作区（`send_home`），和现在一样。对话因此是连续的。
- 不能换目录的驱动只能复制一个主导出来（`lead_note`），这种情况下对话没法连续。新一轮会拿到前几轮的总结作为开场信息，对话里插一条分隔，写明“这一轮的主导是新开的会话”。
- 新一轮的开场信息（`brief::kickoff`）加一段：本组前几轮的标题、状态、是否落地、总结的第一行，最多列 5 轮。

### 3.5 页面

- 路由 `#/work/<id>`：一个工作组。`#/runs/<id>` 保留，打开它所属的工作组，并选中这一轮。
- 中间是主导的对话，连续不断；每轮开始的地方插一条分隔“第 N 轮 · 标题 · 状态”（按这一轮的 `created_at` 插在对应位置）。顶部的 run 信息、收尾卡片和任务板显示**当前选中的那一轮**，默认是最新一轮。
- 右侧工具列新增“各轮”窗格（`PaneKind` 加 `rounds`）：每轮一行，写目标、状态、落地情况、检查结果、花费、时间，点一下就选中那一轮，并把对话滚到它的分隔处。
- 侧栏里一个工作组只占一行，标题是工作组的标题，状态点跟着当前一轮走，可以展开看各轮。
- 改主导、换模型：主导会话本身照常可以换模型（`agent_set_model`）。要换成另一个会话当主导，就新建 Work。

### 3.6 提示词

- LEAD 末尾改成：一轮结束后，人还会在这里说话。他提出新的目标时，用 `run_next` 在这里开始下一轮，不要用 `work_start`；问题直接回答。
- `work_start` 被已结束一轮的主导调用时，报错并指向 `run_next`。只有人明确要“另开一个独立的 Work”时，才用 `work_start`。

## 4. 分阶段与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| G1-1 | `works` 表与迁移、`Run.work_id`、事件、`GET /v1/works`、`GET /v1/works/{id}`、`POST /v1/works/{id}/runs`、bindings | 迁移后每个旧 run 都有自己的工作组；同一组第二个未结束的 run 建不出来（409） |
| G1-2 | `run_next` 工具与 §3.3 的分支规则（叠在上一轮上、连带落地、`from: "base"`）；开场信息里的前几轮 | mock-agent 测试：已落地后下一轮从基线开始；没落地时叠在上一轮上，落地新一轮连同上一轮一起进基线、上一轮标为随之落地；`from: "base"` 不带上一轮的改动；进行中再调 `run_next` 被拒 |
| G1-3 | 提示词（§3.6）；`work_start` 对已结束一轮的主导报错并指向 `run_next` | 主导在已结束的一轮里收到新目标时调用 `run_next`，收到问题时只回答（mock 场景） |
| G1-4 | GUI：`#/work/<id>`、对话里的轮次分隔、“各轮”窗格、侧栏一组一行、`#/runs/<id>` 跳到所属工作组；MockBridge 数据 | 同一个页面里连续做三轮不跳页；各轮窗格能切换和定位；截图放 `docs/screens/g1/` |
| G1-5 | CLI：`crossagents run ls` 带工作组；`crossagents work ls/show` | — |

## 5. 待定

- 删除：v1 只能删整个工作组（连同各轮），以及最后一轮。删中间的一轮，会让叠在它上面的轮次失去基线，先不做。
- 工作组的标题：沿用第一轮的标题，还是在每轮之后按话题重新起。先沿用，人可以改名。
