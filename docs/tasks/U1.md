# U1 任务书：免手动升级（本机模式）

> 设计：[MULTI-NODE.md](../MULTI-NODE.md) §13 · 接管机制：[PROCESS-SUPERVISION.md](../PROCESS-SUPERVISION.md) · 2026-10-24

## 1. 问题

GUI 只读 `~/.crossagents/hub.json`，从不启动 hub。2026-10-24 修了驱动却没生效：本机跑着的还是旧版 hub，只能手敲 `hub stop` / `hub start`。发布出去的版本不能指望用户这样做。

## 2. 改动

| 层 | 内容 |
|---|---|
| hub（`paths.rs` `HubFile`） | `hub.json` 多一个 `exe`：hub 运行的可执行文件（`current_exe()`）。GUI 靠它分辨「自己装的 hub」与手动起的 hub；旧 hub 没有这个字段，按外来处理 |
| CLI（`cmd/hub.rs`） | `hub start` 等 hub 就绪的上限从 5 秒改为 30 秒：启动时要探测各厂商的登录（CLI、代理探测），这台机器上约 5 秒，原来的上限会误报失败（`cargo test` 的 `e2e` 因此失败过） |
| 打包（`package.json`） | `win.target` 由 `dir` 改为 `nsis`（一键、按用户安装）；`extraResources` 带上 `target/release/crossagents.exe`（放在 `resources/bin/`）；`publish` 指向公开仓库 `L1nkkkk/CrossAgents-releases` 的 GitHub Releases；`electron:build` 先查版本一致（`scripts/check-version.mjs`）、编 release 版 exe 再打包，`electron:release` 打包并上传 |
| 本机 hub 管理（`electron/localHub.cts`） | 只在安装版（`app.isPackaged`）里跑。启动时：查自带 exe 的 `--version` → 复制到 `<home>/bin/<版本>/`（sha256 相同就跳过，先写 `.partial` 再改名）→ 读 `hub.json` 并请求 `/v1/info` → 按 MULTI-NODE §13.3 的表决定：起、留、换（`hub stop` 后新版 `hub start`）、不降级、外来不碰 → 清理没有进程在用的旧版本目录。请求和事件流先等这一步结束；事件流断开时再查一次（5 秒节流，失败后 30 秒内不重试），起不来时侧栏的离线原因写 `cannot start the local hub: …` |
| GUI 进程（`electron/main.cts`） | 单实例；安装版启动时调 `autoUpdater.checkForUpdatesAndNotify()`，后台下载、退出时安装。安装版没有控制台，对本机 hub 做的每个决定和更新器的输出写进 `<home>/logs/gui.log` |

判断「本机自己的 hub」：`hub.json` 的 `exe` 在 `<home>/bin/` 下。`target/debug` 起的 dev hub、没有 `exe` 的旧 hub、以后的远程 hub 都不会被停或重启，版本比对沿用 API-AUTH §5 的说明页。

## 3. 验收

自动：

- `cargo test --workspace` 通过。
- `apps/gui` 里 `npm run typecheck`、`npm test` 通过。`npm test` 先编译 `electron/` 再跑 `dist-electron/*.test.cjs`：版本比较、哪些 hub 算自己的、起 / 留 / 换 / 不降级 / 外来的决策、复制到版本目录、清理旧目录（Windows 上用一个运行中的程序占住旧目录，验证不删，进程退出后再删）。

手测（用独立的 home，不碰自己的 `~/.crossagents`）：

准备：

```powershell
$env:CROSSAGENTS_HOME = "$env:TEMP\ca-upgrade"
New-Item -ItemType Directory -Force $env:CROSSAGENTS_HOME | Out-Null
# 用 mock agent 冒充 codex，不花额度；不探测本机登录
@"
[accounts]
detect = false
[plugins.codex]
driver = "codex-native"
native_command = ['$PWD\target\release\crossagents-mock-agent.exe', "app-server"]
"@ | Set-Content -Encoding utf8 "$env:CROSSAGENTS_HOME\config.toml"
```

1. 打 0.1.0 的包：`cd apps/gui; npm run electron:build`。启动 `release\win-unpacked\CrossAgents.exe`（或装 `release\CrossAgents Setup 0.1.0.exe`）。要让 GUI 用上面的 home，从设了 `CROSSAGENTS_HOME` 的同一个终端启动。
   - 期望：`<home>\bin\0.1.0\crossagents.exe` 出现；`hub.json` 的 `exe` 指向它；侧栏连上，版本 v0.1.0。没有手敲任何命令。
2. 让一个 agent 在跑：

   ```powershell
   $ca = "$env:CROSSAGENTS_HOME\bin\0.1.0\crossagents.exe"
   & $ca agent add --plugin codex --role worker --display-name Mira mira
   & $ca send mira "[slow] keep going"
   & $ca hub status   # agent processes 里记下宿主的 pid
   ```
3. 关掉 GUI。把 Cargo workspace 与 `apps/gui/package.json` 的版本都改成 0.1.1，`npm run electron:build`（输出会覆盖 `release\`，先把 0.1.0 的那份挪开也行）。启动新包。
   - 期望：`<home>\bin\0.1.1\` 出现；`hub.json` 的 `version` 是 0.1.1、`exe` 指向 0.1.1；`hub status` 里 agent 进程的 pid 不变，mira 的轮次还在跑（`crossagents agent cancel mira` 能取消它），GUI 里 mira 照常显示。`bin\0.1.0\` 还在（被接管的宿主还从那里跑）。
4. `& "$env:CROSSAGENTS_HOME\bin\0.1.1\crossagents.exe" agent stop mira`，关掉再打开 GUI。
   - 期望：`bin\0.1.0\` 被删掉，`bin\0.1.1\` 保留。
5. 外来 hub 不被碰：`hub stop`，用 `target\debug\crossagents.exe hub start` 起一个 dev hub，再打开 GUI。
   - 期望：GUI 直接连这个 dev hub，`hub.json` 的 `exe` 仍指向 `target\debug`，没有被停掉重启。
6. 不降级：在 0.1.1 的 hub 跑着时启动 0.1.0 的包。
   - 期望：hub 仍是 0.1.1。

收尾：`hub stop --agents`，删掉 `$env:TEMP\ca-upgrade`，把版本号改回去。

每一步 GUI 的决定都能在 `<home>\logs\gui.log` 里看到（`local hub: start / keep / replace / newer / foreign`、`removed old versions …`）。

2026-10-24 实测（`win-unpacked`，未安装；`[hub] port = 0`）：

| 步骤 | 结果 |
|---|---|
| 1 | `local hub: start, shipped 0.1.0`；`hub.json` 的 `exe` 指向 `bin\0.1.0\crossagents.exe` |
| 2 | mira 的轮次在跑，宿主 pid 13196 |
| 3 | `local hub: replace (running 0.1.0 …), shipped 0.1.1`；事件里 `hub.stopping` → `agent.adopted … turn … goes on` → `hub.started version 0.1.1`；宿主 pid 仍是 13196，`agent cancel` 后轮次以 `cancelled` 结束；`bin\0.1.0` 保留 |
| 4 | 重开后 `keep`，`removed old versions 0.1.0` |
| 5 | dev hub（`target\debug`）的 pid 不变，GUI 没有停它 |
| 6 | `local hub: newer (running 0.1.1 …), shipped 0.1.0`，hub 仍是 0.1.1 |

GUI 与 hub 之间有已建立的连接（事件流）。在线更新这一半没测：发布仓库还不存在，更新器报 404 后照常运行。
