# M0 任务书：骨架、hub 与本地 API

> 依据：[DESIGN.md](../DESIGN.md) §2、§4、§11–14 · 状态：已完成 · 2026-10-21

## 1. 目标

搭好 CrossAgents 的工程骨架，跑通「CLI → 本地 API → hub → SQLite → 事件流」这条主干。
M0 不接任何 agent，但之后每个里程碑都只是往这条主干上挂东西。

**完成标志（演示脚本）**：

```
crossagents hub start                 # 后台启动 hub
crossagents hub status                # 显示 running、端口、pid、版本
crossagents events --follow &         # 另开终端实时看事件
crossagents agent add alice --plugin claude --model haiku --role worker --cwd .
crossagents agent ls                  # 列出 alice；events 终端出现 agent.created
crossagents agent rm alice            # events 终端出现 agent.removed
crossagents hub stop
crossagents hub start && crossagents agent ls   # 重启后数据仍在
```

## 2. 范围

**做**

- Cargo workspace 与 5 个 crate：`core`、`api-types`、`store-sqlite`、`hub`、`cli`
- core：ID、领域模型、任务状态机、事件、`Store` / `EventSink` trait、错误类型
- SQLite 持久化：全部表结构（DESIGN §12），M0 只实际读写 `agents` 和 `events`
- hub：数据目录、配置、单实例锁、令牌认证、HTTP API、SSE 事件流（支持断点续传）、日志
- CLI：`hub start|stop|status|run`、`agent add|ls|show|rm`、`events [--follow] [--since]`
- API 类型自动生成 TypeScript
- 单元测试 + API 集成测试

**不做**

- 启动 agent、插件、驱动、MCP、编排、worktree（M1 起）
- 其余扩展点 trait（`AgentPlugin`、`Driver`、`WorkspaceProvider`、`Verifier`、`Policy`、`Pipeline`、`Tool`）：
  在各自的里程碑里随第一个实现一起定义，避免写出没被用过的接口
- GUI、CI 流水线、发布打包

## 3. 技术约定

| 项 | 约定 |
|---|---|
| 工具链 | `rust-toolchain.toml` 固定 `1.99`；edition 2024；workspace resolver 3 |
| 异步 | tokio（multi-thread） |
| HTTP | axum；SSE 用 `axum::response::sse` |
| 数据库 | **sqlx（sqlite，runtime 查询，不用编译期宏校验）** + `sqlx::migrate!` 内嵌迁移 |
| 序列化 | serde / serde_json；枚举一律 `#[serde(rename_all = "snake_case")]` |
| ID | UUID v7（时间有序），newtype 包装 |
| 时间 | `chrono::DateTime<Utc>`，序列化为 RFC 3339 |
| 错误 | 库 crate 用 `thiserror`；二进制用 `anyhow` |
| 日志 | `tracing` + `tracing-subscriber`；hub 写 `<home>/logs/hub.log`（`tracing-appender` 按天滚动） |
| TS 生成 | `ts-rs`，输出到 `bindings/`（仓库根目录） |
| 动态分发的异步 trait | `async-trait` |
| CLI | clap（derive）；HTTP 客户端 reqwest（rustls） |
| 质量门槛 | `cargo fmt --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace` 全部通过 |

> 数据库由 rusqlite 改为 sqlx：原生异步、自带迁移，和 tokio/axum 配合更顺（DESIGN §13 已同步）。

### T1 core：ID、领域模型、任务状态机、错误

- **目标**：定义全系统共用的领域类型。
- **范围**：仅 `crates/core/`。
- **接口约定**：

```rust
// ids.rs —— 用宏生成，避免重复
pub struct AgentId(Uuid);   // 同样：RunId、TaskId、SessionId、MessageId
impl AgentId { pub fn new() -> Self /* Uuid::now_v7 */ }
// 实现 Display / FromStr / Serialize / Deserialize（序列化为字符串）

// model.rs
pub enum Role { Planner, Worker, Reviewer }
pub enum AgentStatus { Stopped, Starting, Idle, Running, Error }

pub struct Agent {
    pub id: AgentId,
    pub name: String,            // 唯一；^[a-z][a-z0-9_-]{0,31}$
    pub plugin: String,          // 如 "claude"
    pub driver: Option<String>,  // None = 插件默认
    pub model: Option<String>,
    pub role: Role,
    pub cwd: PathBuf,
    pub config: serde_json::Value, // 插件私有配置，core 不解释
    pub status: AgentStatus,
    pub created_at: DateTime<Utc>,
}
pub fn validate_agent_name(name: &str) -> Result<(), CoreError>;

pub enum RunStatus { Planning, AwaitingApproval, Running, Completed, Failed, Cancelled }
pub struct Run { id, title: String, planner: Option<AgentId>, status: RunStatus, created_at, updated_at }

pub struct TaskSpec {
    pub goal: String,
    pub scope: Scope,                 // Scope { allow: Vec<String>, deny: Vec<String> }（glob）
    pub interfaces: Vec<String>,
    pub acceptance: Vec<String>,      // 验收命令
    pub references: Vec<String>,
}
pub struct Task { id, run_id: RunId, parent: Option<TaskId>, title: String, spec: TaskSpec,
                  assignee: Option<AgentId>, status: TaskStatus, attempts: u32, created_at, updated_at }

// state.rs —— DESIGN §7.1
pub enum TaskStatus { Pending, Running, WaitingAnswer, Verifying, Retrying, Escalated,
                      Reviewing, Passed, Merged, Failed, Cancelled }
impl TaskStatus {
    pub fn can_transition_to(self, next: TaskStatus) -> bool;
    pub fn is_terminal(self) -> bool;     // Merged | Failed | Cancelled
}

// error.rs
#[derive(thiserror::Error)]
pub enum CoreError { InvalidName(String), InvalidTransition { from, to }, NotFound { kind: &'static str, id: String },
                     Conflict(String), Storage(String) }
```

  - 合法迁移表：`Pending→Running`；`Running→WaitingAnswer|Verifying`；`WaitingAnswer→Running`；
    `Verifying→Passed|Retrying|Escalated`；`Retrying→Running`；`Escalated→Running`；
    `Passed→Reviewing|Merged`；`Reviewing→Passed|Retrying`；任意非终态 `→Failed|Cancelled`
- **验收**：`cargo test -p crossagents-core`，至少覆盖：全部合法迁移为 true、若干非法迁移为 false、终态不可迁出、名字校验的正反例、ID 序列化往返。
- **参考**：DESIGN §4、§7。

### T2 core：事件、EventSink、Store

- **目标**：定义事件模型和持久化抽象。
- **范围**：仅 `crates/core/`。
- **接口约定**：

```rust
// event.rs
pub const EVENT_SCHEMA_VERSION: u32 = 1;

pub struct Event {
    pub seq: u64,                 // 由 Store 分配，全局单调递增；未入库时为 0
    pub id: Uuid,                 // v7
    pub ts: DateTime<Utc>,
    pub schema: u32,
    pub kind: EventKind,
}

#[serde(tag = "type", content = "data", rename_all = "snake_case")]
pub enum EventKind {          // 序列化后 type 形如 "agent.created" —— 用 #[serde(rename = "agent.created")]
    HubStarted { version: String },
    HubStopping,
    AgentCreated { agent: Agent },
    AgentRemoved { id: AgentId, name: String },
    AgentStatusChanged { id: AgentId, from: AgentStatus, to: AgentStatus },
    // 以后的里程碑在这里追加；只追加不修改
}

#[async_trait]
pub trait EventSink: Send + Sync {
    async fn handle(&self, event: &Event);
}

// store.rs
#[async_trait]
pub trait Store: Send + Sync {
    async fn insert_agent(&self, agent: &Agent) -> Result<(), CoreError>;   // 名字重复 → Conflict
    async fn get_agent(&self, key: &AgentKey) -> Result<Agent, CoreError>;  // NotFound
    async fn list_agents(&self) -> Result<Vec<Agent>, CoreError>;
    async fn delete_agent(&self, id: AgentId) -> Result<(), CoreError>;
    async fn update_agent_status(&self, id: AgentId, status: AgentStatus) -> Result<(), CoreError>;

    async fn append_event(&self, kind: EventKind) -> Result<Event, CoreError>; // 分配 seq/id/ts 后返回
    async fn events_since(&self, seq: u64, limit: u32) -> Result<Vec<Event>, CoreError>;
}
pub enum AgentKey { Id(AgentId), Name(String) }
```

  - `EventBus`（放在 core，不是扩展点）：持有 `Arc<dyn Store>` 与 `tokio::sync::broadcast::Sender<Event>`（容量 1024）
    以及 `Vec<Arc<dyn EventSink>>`。`publish(kind)` = 先 `append_event` 入库，再广播，再依次调用 sinks。
    `subscribe()` 返回 `broadcast::Receiver<Event>`。
- **验收**：`cargo test -p crossagents-core` 通过；用一个内存 `Store` 测试替身验证 `EventBus::publish` 先入库、后广播、seq 递增，sink 被调用。
- **参考**：DESIGN §2 原则 2、§5。

### T3 api-types：API 数据结构 + TS 生成

- **目标**：定义本地 API 的请求、响应、错误格式，并生成 TypeScript。
- **范围**：`crates/api-types/`、`bindings/`。
- **接口约定**：
  - 直接复用 core 的 `Agent`、`Event` 等类型时，在 core 中给它们加 `#[cfg_attr(feature = "ts", derive(TS))]`，
    core 增加可选 feature `ts`；`api-types` 开启它。core 默认不依赖 ts-rs。
  - 类型：

```rust
pub const API_VERSION: &str = "v1";
pub struct HealthResponse { pub status: String /* "ok" */, pub version: String, pub api: String, pub uptime_secs: u64 }
pub struct HubInfo { pub version: String, pub api: String, pub pid: u32, pub home: String, pub started_at: DateTime<Utc> }
pub struct CreateAgentRequest { pub name: String, pub plugin: String, pub driver: Option<String>,
                                pub model: Option<String>, pub role: Role, pub cwd: String,
                                #[serde(default)] pub config: serde_json::Value }
pub struct ListAgentsResponse { pub agents: Vec<Agent> }
pub struct ApiError { pub error: ApiErrorBody }
pub struct ApiErrorBody { pub code: ErrorCode, pub message: String }
pub enum ErrorCode { BadRequest, Unauthorized, NotFound, Conflict, Internal }
```

  - TS 导出：每个类型 `#[ts(export, export_to = "../../bindings/")]`；`cargo test -p crossagents-api-types` 时生成。
- **验收**：`cargo test -p crossagents-api-types` 后 `bindings/` 下出现 `Agent.ts`、`Event.ts`、`EventKind.ts`、`CreateAgentRequest.ts`、`ApiError.ts` 等文件；
  一个 serde 往返测试确认 `EventKind` 序列化为 `{"type":"agent.created","data":{...}}`。
- **参考**：DESIGN §11。

### T4 store-sqlite：迁移与 Store 实现

- **目标**：用 SQLite 实现 `Store`。
- **范围**：`crates/store-sqlite/`（含 `migrations/`）。
- **接口约定**：
  - `SqliteStore::open(path: &Path) -> Result<Self>`：创建文件、开启 WAL、`foreign_keys=ON`、执行 `sqlx::migrate!`
  - `SqliteStore::open_in_memory()` 供测试
  - 迁移 `0001_init.sql` 建全部表：

| 表 | 关键列 |
|---|---|
| `agents` | `id TEXT PK`, `name TEXT UNIQUE NOT NULL`, `plugin`, `driver`, `model`, `role`, `cwd`, `config TEXT(JSON)`, `status`, `created_at` |
| `runs` | `id PK`, `title`, `planner_id → agents`, `status`, `created_at`, `updated_at` |
| `tasks` | `id PK`, `run_id → runs`, `parent_id → tasks`, `title`, `spec TEXT(JSON)`, `assignee_id → agents`, `status`, `attempts`, `created_at`, `updated_at` |
| `messages` | `id PK`, `from_id`, `to_id`, `body`, `created_at`, `delivered_at` |
| `events` | `seq INTEGER PRIMARY KEY AUTOINCREMENT`, `id TEXT UNIQUE`, `ts`, `schema INTEGER`, `type TEXT`, `data TEXT(JSON)` |
| `usage` | `id PK`, `run_id`, `task_id`, `agent_id`, `model`, `role`, `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_write_tokens`, `ts` |

  - `events` 上建 `type` 索引；`tasks` 上建 `run_id`、`status` 索引
  - 删除 agent：`runs.planner_id`、`tasks.assignee_id` 使用 `ON DELETE SET NULL`
- **验收**：`cargo test -p crossagents-store-sqlite`：agent 增删查、重名返回 `Conflict`、不存在返回 `NotFound`、
  事件 seq 严格递增、`events_since` 分页正确、重新打开同一文件后数据仍在（用临时目录）。
- **参考**：DESIGN §12。

### T5 hub：服务进程与本地 API

- **目标**：实现 hub 进程：数据目录、单实例、认证、API、SSE。
- **范围**：`crates/hub/`。
- **接口约定**：
  - `pub struct HubConfig { home: PathBuf, port: u16 }`；`HubConfig::load()` 按 §3.2 解析，端口 0 表示随机
  - `pub async fn run(config: HubConfig, shutdown: impl Future) -> Result<()>`：
    获取锁 → 打开 store → 确保 token → 绑定 `127.0.0.1:port` → 写 `hub.json`（含实际端口）→ 发布 `hub.started` → 服务 → 收到关闭后发布 `hub.stopping`、删除 `hub.json`
  - 认证：除 `/v1/health` 外所有路由要求 `Authorization: Bearer <token>`，否则 401 + `ApiError`
  - 路由：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/health` | `HealthResponse`，免认证 |
| GET | `/v1/info` | `HubInfo` |
| GET | `/v1/agents` | `ListAgentsResponse` |
| POST | `/v1/agents` | `CreateAgentRequest` → 201 + `Agent`；校验名字；`cwd` 规范化为绝对路径且必须存在；发布 `agent.created` |
| GET | `/v1/agents/{id_or_name}` | `Agent` |
| DELETE | `/v1/agents/{id_or_name}` | 204；发布 `agent.removed` |
| GET | `/v1/events?since=<seq>` | SSE；也接受 `Last-Event-ID` 头 |
| POST | `/v1/shutdown` | 202，随后优雅退出 |

  - SSE 细节（防止丢事件）：**先** `subscribe()` 广播，**再**从库里补发 `seq > since` 的历史事件，
    之后转发广播时跳过 `seq <= 已发送的最大 seq` 的事件。每条 SSE 的 `id` = seq，`event` = 事件类型，`data` = 事件 JSON。
    每 15 秒发一次 keep-alive。广播接收方落后（`Lagged`）时，从库里按 seq 补齐再继续。
  - `CoreError` → HTTP 状态码映射：`NotFound→404`、`Conflict→409`、`InvalidName/InvalidTransition→400`、其他 → 500
- **验收**：`cargo test -p crossagents-hub` 的集成测试（临时 home、端口 0、reqwest）：
  无 token 访问 `/v1/agents` 得 401；创建、列出、按名查询、删除 agent；重名 409；
  订阅 `/v1/events?since=0` 后能按顺序收到 `hub.started`、`agent.created`、`agent.removed`；
  同一 home 启动第二个 hub 失败；`/v1/shutdown` 后 `hub.json` 被删除。
- **参考**：DESIGN §11、§12。

### T6 cli：`crossagents` 命令

- **目标**：实现 M0 的命令行。
- **范围**：`crates/cli/`。
- **接口约定**：
  - 客户端从 `<home>/hub.json` 读端口、从 `<home>/token` 读令牌；hub 未运行时提示 `hub 未运行，请先执行 crossagents hub start`，退出码 1
  - 命令：

| 命令 | 行为 |
|---|---|
| `hub run` | 前台运行 hub（Ctrl+C 优雅退出） |
| `hub start` | 以后台进程启动 `crossagents hub run`（Windows：`DETACHED_PROCESS \| CREATE_NEW_PROCESS_GROUP \| CREATE_NO_WINDOW`；Unix：`setsid`），轮询 `/v1/health` 最多 5 秒，成功后打印端口与 pid；已在运行则提示并返回 0 |
| `hub stop` | 调 `/v1/shutdown`，等待 `hub.json` 消失（最多 5 秒） |
| `hub status` | 打印 running/stopped、端口、pid、版本、运行时长 |
| `agent add <name> --plugin <p> [--driver] [--model] --role <r> [--cwd <dir>]` | `cwd` 默认当前目录 |
| `agent ls` | 表格：name、plugin、model、role、status、cwd |
| `agent show <name>` | 详细信息 |
| `agent rm <name>` | 删除 |
| `events [--since N] [--follow]` | 不带 `--follow` 打印历史后退出；带则持续输出。每行：`#seq 时间 类型 摘要` |

  - 全局参数 `--json`：以 JSON 输出，供脚本使用
  - 错误时输出 `ApiError.message`，非 0 退出
- **验收**：手工执行 §1 的演示脚本全部符合预期；`cargo test -p crossagents-cli` 至少覆盖参数解析。
- **参考**：DESIGN §10。

## 5. 风险与注意

| 风险 | 应对 |
|---|---|
| Windows 后台进程与文件锁行为和 Unix 不同 | T5/T6 在 Windows 上实测；锁用 `fs4`，不要用 pid 文件判断存活 |
| crates.io 下载慢 | 必要时在 `~/.cargo/config.toml` 配置 rsproxy 镜像（`[source.crates-io] replace-with = "rsproxy-sparse"`） |
| SSE 丢事件或重复 | 严格按 T5 的「先订阅、再补历史、按 seq 去重」实现，并有测试覆盖 |
| `EventKind` 以后不断扩展导致客户端崩溃 | 客户端遇到未知 `type` 时忽略；只追加变体，不改已有字段 |
| ts-rs 与 chrono/uuid 的兼容 | 开启 ts-rs 的 `chrono-impl`、`uuid-impl`、`serde-json-impl` feature |
