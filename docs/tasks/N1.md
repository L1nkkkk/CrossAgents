# N1 任务书：原生驱动第一阶段（Driver trait + codex-native）

> 依据：[DESIGN.md](../DESIGN.md) §2、§4.1、§9、§13、§14 · 实测：[codex-app-server.md](../research/codex-app-server.md) ·
> 状态：已完成（codex-cli 0.158.0 上冒烟测试通过） · 2026-10-21

## 1. 范围

在 hub 和各家 agent 之间加一层自己的驱动接口，再接上第一个原生驱动：

- `core` 定义 `Driver` / `DriverSession` trait、能力表 `Capabilities`、统一会话事件 `SessionEvent`。
- 现有 ACP 驱动改实现新 trait，即 `acp-generic`，行为不变（仍是一进程一会话）。
- 新增 `codex-native`：对接官方 `codex app-server`，一个 Profile 一个进程，进程内一个线程对应一个会话。
- Profile（现阶段仍叫 plugin）增加 `driver` 字段：`codex-native` / `claude-native` / `acp-generic`，缺省 `acp-generic`。

不在本阶段：编排流程、GUI、工作区管理、Claude 原生驱动、hub 侧的自动挂起与恢复（见 §6）。

```toml
# ~/.crossagents/config.toml
[plugins.codex]
driver = "codex-native"                 # 不写则仍走 codex-acp
# native_command = ["codex", "app-server"]   # 默认值
```

```
crossagents agent add coder --plugin codex --driver codex-native --account work --model gpt-6-luna --role worker
```

## 2. 接口

```rust
pub trait Driver: Send + Sync {                // 一个 Profile 一个实例
    fn name(&self) -> &str;
    fn kind(&self) -> DriverKind;
    fn capabilities(&self) -> Capabilities;
    fn models(&self) -> Vec<String>;
    async fn open(&self, spec: SessionSpec) -> Result<Box<dyn DriverSession>, CoreError>;
    async fn resume(&self, session_id: &str, spec: SessionSpec) -> Result<Box<dyn DriverSession>, CoreError>;
}

pub trait DriverSession: Send + Sync {         // 一个会话（Worker / Planner）
    fn session_id(&self) -> &str;              // 厂商的会话 id：ACP session id、Codex thread id
    async fn prompt(&self, text: &str) -> Result<TurnOutcome, CoreError>;   // 一轮跑完才返回
    async fn interrupt(&self) -> Result<(), CoreError>;
    async fn suspend(&self) -> Result<(), CoreError>;                       // 释放资源，之后用 Driver::resume
    async fn fork(&self, at_turn: Option<&str>, spec: SessionSpec) -> Result<Box<dyn DriverSession>, CoreError>;
    async fn rollback(&self, before_turn: &str, revert_files: bool) -> Result<(), CoreError>;
    async fn set_model(&self, model: Option<&str>, effort: Option<&str>) -> Result<(), CoreError>;
    async fn compact(&self) -> Result<(), CoreError>;
    async fn shutdown(&self);
}
```

可选操作有默认实现，返回 `CoreError::Unsupported`；调用方先看能力表。

| 能力 | `codex-native` | `acp-generic` |
|---|---|---|
| `streaming`、`interrupt`、`mcp`、`usage` | ✓ | ✓ |
| `multi_session`、`resume`、`fork`、`rollback`、`set_model` | ✓ | — |
| `revert_files` | —（上游只回退历史） | — |
| `structured_diff`、`rate_limits`、`permission_callback`、`compaction` | ✓ | — |

统一事件 `SessionEvent { kind, raw }`，`raw` 是翻译前的厂商消息。`kind`：`Started`、`TurnStarted`、`Output`（文本 / 思考）、
`ToolCall`、`ToolCallUpdated`、`TurnDiff`、`Usage`（含累计 token 分项）、`RateLimits`、`PermissionRequested`、`TurnCompleted`、
`Warning`、`Error`、`Exited`。

本地 API：`GET /v1/plugins` 的每项多了 `driver`；`capabilities` 换成上表的字段（`model_switch` → `set_model`，
`usage_report` → `usage`，GUI 未使用这两个字段）。`POST /v1/agents` 的 `driver` 取值不合法时返回 400。

## 3. codex-native 的做法

| 项 | 做法 | 依据 |
|---|---|---|
| 进程 | 按「启动命令 + 环境变量」共享一个 `codex app-server`；最后一个会话关闭或挂起时进程退出 | 实测一进程多线程、并发轮次 |
| 账号隔离 | 沿用 M5：账号的 `CODEX_HOME` 进入进程环境，所以不同账号必然是不同进程 | `Accounts::agent_env` |
| 启动 | 找到 npm 包装脚本背后的原生 `codex.exe` 直接启动；进程工作目录用临时目录 | 杀 `codex.cmd` 会留下孤儿进程；Windows 上进程的工作目录删不掉 |
| 开会话 | `thread/start`：`model`、`cwd`、`sandbox`、`approvalPolicy`、`developerInstructions`、`config.mcp_servers` | — |
| 协作工具 | `crossagents mcp` 以 `config.mcp_servers.crossagents` 按线程挂载，并设 `default_tools_approval_mode = "approve"` | 不设则 `never` 策略下 MCP 调用被拒 |
| 权限 | 默认放行：`danger-full-access` + `never`；`Deny`：`workspace-write` + `on-request` 并拒绝所有请求；`config.sandbox` / `config.approval` 可覆盖；给了 `PermissionHandler` 就问它 | §4.4；Windows 上 `workspace-write` 需先装好 Windows 沙箱 |
| 发消息 | `turn/start`，等 `turn/completed`；会话忙时拒绝（Conflict），排队留给 hub | 忙线程上的 `turn/start` 会并入当前轮 |
| 挂起 / 恢复 | `thread/unsubscribe` 后释放；恢复用 `thread/resume{threadId}`，重新传全套设置 | 实测关进程后恢复成功 |
| 分叉 / 回退 | `thread/fork{lastTurnId}`（在同一进程，即同一账号）/ `thread/revert{beforeTurnId}` | 分叉不继承设置，必须重传 |
| 换模型 | 记下，下一次 `turn/start` 带 `model` / `effort`；`config.effort` 给初值 | 对本轮及之后生效 |
| 用量归属 | `clientInfo.name = "crossagents"`，rollout 的 `originator` 即为它，M5 照常归属 | 实测 |

## 4. 设计决定

| 决定 | 原因 |
|---|---|
| trait 拆成 `Driver`（Profile 级）与 `DriverSession`（会话级），而不是 §9.2 草稿里一个 trait 带 `session` 参数 | 会话持有自己的事件通道和轮次状态；codex 的进程池放在 `Driver` 里，自然对应「一个 Profile 一个进程」 |
| `rollback(before_turn, …)` 而不是 `rollback(to_turn, …)` | 与上游语义一致：去掉指定轮及之后；含义不含糊 |
| `resume` 在 `Driver` 上，以会话 id 为参数 | 挂起后没有活的会话对象可调；id 就是 `Started` 事件里报的那个 |
| 能力表增加 `streaming`、`interrupt`、`mcp`、`multi_session` | 前三项原来就有；`multi_session` 决定以后能否把 ACP 也改成共享进程 |
| 统一事件用 `{kind, raw}` 包一层 | 每个事件都能带原始消息，而不必给每个变体加字段 |
| 回合边界、diff、限额、权限事件暂不发成 hub 事件 | 本阶段只到驱动层；hub 事件和 GUI 展示放下一阶段，免得先定死 API |
| `claude-native` 先降级为 `acp-generic` 并发警告 | DESIGN §9.4：原生驱动不可用时同一 Profile 走 ACP 兜底 |
| 冒烟测试必须显式给 `CROSSAGENTS_SMOKE_CODEX_HOME` | 测试不得默认碰 `~/.codex` |

## 5. 验收

- `cargo fmt --check`、`cargo clippy --all-targets`、`cargo test` 全部通过；ACP 原有测试只改了调用方式，断言不变。
- `mock-agent app-server` 模拟协议核心子集（线程开启 / 恢复 / 分叉 / 回退、轮次、中断、审批、diff、用量、限额，线程存到 `$CODEX_HOME`），
  `crates/mock-agent/tests/codex_native.rs` 覆盖：流式与轮次事件、MCP 与开场说明、同账号共用进程且不同账号分开、中断、
  三种权限路径、挂起后在新进程恢复、分叉与回退、换模型与 diff、失败与崩溃；`codex_hub.rs` 走 hub 全链路并检查账号的 `CODEX_HOME`。
- 真实 Codex 冒烟（默认忽略）：开会话、发消息、权限请求、中断、挂起 → 进程退出 → 恢复并接着对话、回退与分叉。

```
CROSSAGENTS_SMOKE_CODEX_HOME=<已登录的 CODEX_HOME> [CROSSAGENTS_SMOKE_MODEL=<模型>] \
  cargo test -p crossagents-drivers --test codex_smoke -- --ignored --test-threads=1
```

2026-10-21 在 codex-cli 0.158.0（Windows）上 5 项全部通过。

## 6. 留给下一阶段

- **Claude 原生驱动**：按 §14 实测 Agent SDK 侧车与 stream-json，定 `claude-native` 的实现。
- **hub 用上新能力**：空闲挂起与来消息恢复（会话 id 已在 `agent.session_started` 里）；回合、diff、限额、权限请求的 hub 事件与 API；
  `PermissionHandler` 接 Planner / 人；GUI 按能力表显示回退、分叉、按轮改动、换模型。
- **ACP 一进程多会话**，以及 ACP 的 `session/load` 恢复（§14 最后一项）。
- **拆 Profile 和会话**：现在 Profile 还是 `[plugins.<name>]`，会话还是 `Agent`；`driver` 同时存在于两处（Profile 默认、会话覆盖）。
- **版本告警**（§9.4）：记录对接的上游版本（`codex_native::wire::VERIFIED_VERSION`），版本不在已验证范围时警告。
- M5 用量统计按会话 id 去重：`thread/revert` 会生成第二个 rollout 文件，同一线程可能被算两次。
- 未确认项见实测报告 §8：思考流何时出现、单进程线程上限、空闲线程是否被服务端卸载、Windows 沙箱装好后的边界。
