# Cutex desktop 前端拆解：哪些可以借给 CrossAgents

> 来源：[senxiu-official/cutex-desktop](https://github.com/senxiu-official/cutex-desktop) `79e716b`（0.1.5 "First Take"，2026-10-21）· 2026-10-22
> 方法：读它的 `docs/DESIGN.md`（§4 UI 每条决定都写了日期和理由）、`CHANGELOG.md`，以及 `apps/desktop/src/renderer` 里关键组件和 `lib/` 纯函数的头注释。没有运行，下面没有截图。

## 0. 先说结论

Cutex 和 CrossAgents 要解决的是同一件事：**守护进程管着一群 agent，桌面端只是客户端，agent 之间互相派活**。它是 Electron + React 19 + Tailwind 4 + Zustand，参考 ZCode 的组件，走得比我们远很多。

两边的模型差别：

| | Cutex | CrossAgents |
|---|---|---|
| 组织 | 项目 = 工作区 + 团队，可选一个 Director | run = 一次需求，Planner 带一组 Worker / Reviewer |
| 派活 | **委托（ask）**：任何 agent 都能委托任何 agent，cutex 排队、执行、回传结果，可以要求验收 | **任务**：Planner 提交计划，人审批后 engine 派给 Worker，Reviewer 审，合并到集成分支 |
| agent 间消息 | Agent Bus，带投递方式（本轮后 / 尽快 / 打断） | engine 把消息发给 Planner / Worker |

所以 Cutex 的「委托」几乎可以一对一换成我们的「任务」，它对委托做的所有界面（卡片、状态表、分组、需要你）都可以直接拿来用。

它也有明显的反面：`Composer.tsx` 1466 行，队列面板有十几条规则，多主机、设备权限、插件沙箱、内置浏览器都做了。**借它的结构和规则，不借它的复杂度。**

## 1. 时间线（对话）

### 1.1 工具步骤的折叠规则（P0）

`DESIGN §4.14`，代码在 `lib/workGroups.ts`（纯函数，有测试）：

- 时间线里的条目分两类。**可折叠**：命令、文件编辑、MCP 工具、网页搜索、subagent 操作、推理。**不可折叠**：agent 正文、用户消息、agent 间消息、审批和提问。
- 一串可折叠条目在后面出现不可折叠条目之前**保持展开**，只显示最新 3 步，更早的折成「N 个更早的步骤」。
- 后面出现不可折叠条目时，这一串折成**一句话**：`✓ 4 个命令 · 改了 2 个文件 · 1 次工具调用 · 41s`。有失败时是红色 ✗ 加「N 个失败」，失败的步骤留在这一句下面不折。
- 只有一步的串永远不折；手动展开或收起优先于自动状态。
- 正在运行的命令在行内显示最后 3 行输出。

**本轮状态放在底部**：新内容出现在最下面，所以状态也在最下面：`••• 42s · 推理中`，「推理中」会换成 运行命令 / 修改文件 / 等待你确认 / 回复中 / 撰写计划。一轮结束后，轮头补上「已工作 1m 30s」和时间。

→ 我们现在是「只显示最近 4 条工具调用」，这套规则更好，可以照搬：把 `session.ts` 的折叠改成「按可折叠 / 不可折叠分串」。

### 1.2 agent 间消息的紧凑行（P0）

`DESIGN §4.2 / §4.15`，`components/BusMessage.tsx`：

- 只有**人发的消息**靠右；收到的和发出的 agent 消息都靠左，表头互为镜像：
  - `↙ 来自 [头像] Mika · 本轮后  <一行预览>  ›`
  - `↗ 发给 [头像] Mika`
- 方向同时用文字和箭头表达；收到的箭头用强调色，发出的是灰色。头像总是**对方**的。
- 默认一行，点开看完整气泡；设置里可以切换成完整模式。
- 系统来源（闹钟、任务）是带来源图标的小卡片。

→ 这正好解决 V3 §6 留下的「编排输入（engine 发给 Planner 的提示）与人发的消息区分显示」。engine 发给 Planner 的「T2 已完成」、Worker 的 `task_ask` 都用这种一行，人的消息才是右侧气泡。

### 1.3 委托卡片（P0，对应我们的任务卡片）

`DESIGN §4.21`，`components/DelegationCard.tsx`。委托方的对话里，`agent_delegate` 调用渲染成一行：

```
⇄ 委托 [头像] Helper · model  #3  标题 …………  [主人插话过]  ● 运行中 · 12s ▸
```

- `#N` 是彩色编号（按本次运行中第一次出现的顺序编号，颜色由 id 算出）。在多个地方用同一个编号指同一件事。
- 运行中，标题换成对方的**实时活动**（如 `$ cargo test`）加「· N 个工具」。
- 排队或受阻时多一行：排在第几位、在等什么。
- 展开：委托内容、进度（最近 5 条进度记录，带时间）、提问（已回答 / 已转给主人）、结果（预览、用时、查看完整）、操作（打开对方、停止、重试、验收通过、放弃）。停止和放弃要点两次，第一次把卡片变红。
- 同一个菜单用在卡片、列表行和状态胶囊上（`delegationMenu`）。

→ Planner 对话里，每个派出的任务就是一张这样的卡片：`⇄ T2 [Rex 头像] 安全审查 · ● 运行中 · 3m ▸`，展开看规格、Worker 的进度、提问、diff stat、验收结果。V3 的「任务抽屉」内容可以整体搬进卡片的展开区。

### 1.4 状态表：符号 + 文字，不单靠颜色（P0）

`DESIGN §4.21` 的状态表是整份文档里最值得照抄的东西：

- 五种符号：○ 等别人、● 运行中（呼吸）、✓ 完成、✕ 没有结果就结束、◌（虚线）停了但能继续。
- 每个状态都是 **符号 + 一个词**，词写清楚在等谁：「排队第 2 位」「等 Rex 结束当前回合」「Rex 离线」「有提问」「待验收」「结果不明」。
- 每个状态归到一个**分组**，分组决定列表的排序和「需要你」的计数：
  - **需要你**：等你审批、结果不明、等你验收、有转给你的提问
  - **等待 / 受阻**：排队、被暂停、对方离线、等对方验收
  - **进行中**
  - **已结束**（折叠，每次加载 50 条）
- 排序：需要你和等待按等得最久的在前；进行中按最近开始在前；已结束按最近结束在前。

→ 我们的任务状态（pending / running / reviewing / merged / failed…）应该按这个思路整理成一张表：每个状态对应哪个符号、哪个词、哪个分组。Run 视图的任务列表按分组排，侧栏和工作区的数字按「需要你」计。表放在 DESIGN 里，GUI 和 CLI 共用同一套词。

### 1.5 轮尾摘要（P1）

`components/TurnSummary.tsx`：一轮结束后，回复下面一行淡色小字：

```
✎ 改了 3 个文件 +12 −4 · [文件链接] · [localhost:5173] · +N ▸
```

展开后每个文件一行（查看变更 → 侧栏打开这一轮的 diff；打开），每个链接可以选侧栏预览、浏览器打开、复制路径。只读的轮次不显示。

→ 这是「按轮看 diff」的入口，比单独做一个 diff 页面更自然。Worker 的每一轮都可以有，任务卡片展开区放整个任务的汇总。

### 1.6 提问和审批停靠在输入框上方（P1）

`DESIGN §4.4`，`components/InteractionDock.tsx`（参考 ZCode）：

- 不是弹窗，是**停靠在输入框上方的卡片**；一次只显示一个，其余排队。
- 显示时输入框隐藏，但草稿保留。
- 键盘操作：↑/↓/Tab、Enter、Esc、数字键 1/2/3 选选项；提问支持多选项加「其他」。
- 侧栏这个 agent 显示 ⚠，同时发系统通知。

→ 对应 V3 §6 的「`ask_user` 与 Worker `task_ask` 作为对话里的提问卡片」。计划审批也可以用这个位置，不用把计划卡片塞在对话末尾。

## 2. 输入框和它上方的区域

### 2.1 「接下来」队列面板（P0）

`DESIGN §4.3`，`components/QueuePanel.tsx`：

- 按键：空闲时 Enter 发送；忙时 **Enter = 排队**、**Ctrl+Enter = 插话（steer，下个工具边界读到）**、**Ctrl+Shift+Enter = 打断并发送这条**；输入框里按 **Esc 中断**。忙时一直有红色「■ 停止」。
- 插话后在时间线里先显示虚线淡色气泡「已插入，等待模型读取」，模型真读到了再变成正常消息。
- 队列是输入框顶边上的一张卡片，标题「接下来 · N」，可以折叠成一行；每条可以编辑、删除、拖动排序、「立即发送」（变成插话）。插话一旦发出不能撤回，排队的可以。
- 停止后队列暂停，单独一段显示，有「继续发送」「放回输入框」「清空」。
- 发送失败的消息留在原位，有「重试」「放回输入框」「丢弃」。
- 队列存在守护进程里，关窗口不丢，CLI 也能看到。

→ 我们现在只提示「忙时会排队」。至少要做到：队列可见、可删、可改；区分排队和插话；停止后不自动发出排队的消息。hub 需要把队列做成可查询的资源。

### 2.2 「需要你」条（P0）

`components/NeedsYouStrip.tsx`：输入框上方一行，每个需要你处理的 agent 一个小标签（头像 + 名字 + 一个状态词），**不包括当前打开的 agent**：

- 需要你和出错的排在前面并着色；其他标签是中性色。
- 两个以上「完成」合成一个「N 个已完成」，点开逐个打开或全部清除。
- 一行放不下就收进「+N」，从不横向滚动（他们试过横向滚动，有人反馈后改掉）。
- 每个标签有 ×：完成的标记为已看；需要你的隐藏到下次状态变化。

→ 多 agent 并行时，人在跟一个 agent 对话，其他 agent 等着你，这条比侧栏更近。我们对应的是：待审批的计划、Worker 提问、待验收、待合并。

### 2.3 状态行和状态胶囊（P1）

`DESIGN §4.20`，`components/StatusBar.tsx`：

- 每类状态是一个独立模块：**目标**、**进程**（模型的 `update_plan` 清单）、终端、subagent、委托、作业。
- 每类可以放在输入框上方的状态行、浮在时间线角落的「胶囊」、两处都放或都不放。
- 胶囊收起时每类一行：目标 = 状态标记 + 目标 + 预算环；进程 = 当前步骤 + 完成数/总数；委托 = 第一个 + 状态和时间 + N。
- 计划更新时胶囊边框闪一下，但不会自己展开；时间线里每轮的清单只占一行「更新了进程 2/4」，点开看清单。

→ Planner 会话里放一个 run 的胶囊：需求一行、任务进度 3/5、在忙的 Worker。我们不需要「放哪里可配置」，固定一个位置即可。

## 3. 侧边栏

`DESIGN §4.1`，`components/AgentRows.tsx`、`lib/statusTail.ts`、`lib/turnUnread.ts`：

- IM 风格：项目 → agent 行。行是两行：头像（右下角状态点）· 名字 · 角色标签（Director / 📌 / 新）· 右侧状态；第二行是**最新动作**（`$ cmd`、`✎ file`、`⚙ server.tool`）或最新消息的开头，实时更新，不显示路径。
- 运行中和空闲的 agent 用一行紧凑模式；空闲的折成「N 个空闲」，离线的折成「离线 (4)」。
- **顺序故意固定**：Director → 置顶 → 名字。他们试过按状态或最近活动排序，行会在鼠标下面跳，所以放弃了。状态只体现在状态点和第二行。
- 行尾状态分三级（`statusTail`）：
  - **需要关注**（需要你、有提问、待审批、出错）：只有「出错」和「等你决定」用实心色块，其余是一个小点加淡色文字；
  - **活动中**：小点，运行中呼吸，加短文字；
  - **无事**（完成、空闲、离线）：淡色文字。
- **未读**：agent 在你没看的时候完成或失败了一轮，显示「完成」「出错」小标签，打开即清除；记录存在本机 localStorage。
- 归档的 agent 不在侧栏，底部只显示「N 个已归档」。

→ 保留我们的节点与轨道设计，借这几条：
- 团队成员行的第二行显示最新动作，比只显示「✻ working」信息多；
- 行尾状态按三级处理，并控制着色的数量；
- 加未读的「完成 / 出错」标签；
- 组内顺序固定，不要随状态跳动。

## 4. 版面

- **两个对话并排**（0.1.5）：在侧栏 Ctrl+单击或中键单击 agent，就在当前对话旁边开第二栏；每栏的发送和停止只作用于自己的 agent；中间分隔条可拖动，双击平分；布局存在本机。
  → **Planner 和某个 Worker 并排**，正好是 CrossAgents 最常见的用法。优先级 P1。
- **右侧工具列**：最多两列，每列最多三个窗格（文件树、改动、终端、预览、subagent 记录）；窗格内容跟着当前聚焦的对话走，别的 agent 的内容不会混进来。窄窗口变成抽屉。
- **subagent 只读视图**：点 🤖 名字，在侧栏打开它的时间线（折叠规则相同），没有输入框，注明「subagent 只接受父 agent 的指令」。
- **顶栏合一**：侧栏开关和主机切换在左，当前 agent 的头像和名字在中间（点开是 agent 菜单），git 分支和 `+N −M` 也在这里（点开改动），右边是侧栏开关和窗口按钮。Windows 用 `titleBarOverlay`，系统按钮跟着主题变色。
- 终端是底部面板（Ctrl+`），PTY 在守护进程里，关面板只是断开，再打开会回放。

## 5. 交互细节规则

这些规则小，但能让整个应用显得一致，可以直接写进我们的 DESIGN：

- **一个地方一份操作列表**：右键菜单和悬停时的 ⋯ 是同一份（`lib/menus.tsx`）。
- **展开箭头只表示状态**：收起永远是 ▸；展开时指向内容所在的方向：内容在下方用 ▾，在上方用 ▴（比如输入框上方的面板）。下拉菜单的 ⌄ 不算展开箭头。弹层按 Esc、点外面或再点标签都会关闭。
- **危险操作点两次**：第一次把行或卡片变红并提示「再点一次确认」，不弹确认框。
- **编辑并重发 = 回退到这条消息之前**，然后把原文放回输入框。**分叉 = 新建一个 agent**；回退还是同一个 agent。
- **时间**：一小时内显示相对时间（刚刚、12 分钟前），之后显示钟点（11:02、昨天 18:40）；悬停显示完整的开始 → 结束。
- **颜色预算**：只有出错和等你决定才着色，其余都用中性色加文字。

## 6. 视觉 token

`apps/desktop/src/renderer/src/styles.css`，结构参考 ZCode 的 `@theme`，值是他们自己的：

| token | 浅色 | 深色 |
|---|---|---|
| `--win`（卡片下面的窗口底色） | `#f1f1f3` | `#0e0e0f` |
| `--bg`（对话） | `#ffffff` | `#161616` |
| `--surface` / `--surface-2` | `#f6f6f7` / `#ececee` | `#1c1c1d` / `#262628` |
| `--fg` / `--fg-muted` / `--fg-subtle` | `#1d1d1f` / `#5f6066` / `#6a6b71` | `#ececec` / `#a4a4aa` / `#86868d` |
| `--accent` | `#3b82f6` | `#60a5fa` |
| `--peer`（agent 消息底色） | `#eef4ff` | `#1f2a3a` |
| `--warn` / `--ok` / `--danger` | 另有 `--warn-text` / `--ok-text`，保证小字对比度 ≥ 4.5:1 | |

- 深色下窗口底色（`#0e0e0f`）比对话区（`#161616`）更暗，对话和侧栏像卡片浮在上面，卡片用很淡的边（`rgba(255,255,255,.06)`）加阴影。
- 浅色有三套配色：素白、纸（`#faf9f5` 暖色）、雾。
- 字体：Inter / Segoe UI / 微软雅黑；等宽 JetBrains Mono / Cascadia Code。图标用 lucide。
- 强调色只有一种蓝，和我们只用靛蓝的思路一致。值得借的是 **`--peer` 给 agent 消息一个专门的底色**，以及**状态色分 fill 和 text 两个 token**。

## 7. 工程做法

- **mock bridge**：`preview:web` 在普通浏览器里跑渲染进程，数据来自 `dev/mockBridge.ts`，每个模块的假数据放在自己的 `mock.ts`，生产包会丢掉。调 UI 不需要起守护进程。
  → 我们现在用 mock 插件起完整 hub 来看 GUI，可以加一个纯前端的 mock 模式，调样式快很多。
- **状态逻辑写成纯函数并测试**：`workGroups`、`statusTail`、`agentAttention`、`delegations`、`time` 都有单元测试，组件只负责渲染。
- **模块 + 插槽**：每个功能是一个模块，往命名插槽（导航、页面、状态类别、设置页、时间线渲染器）里放东西；规定「至少两个功能用到同一个位置才做成插槽」。
- **每条设计决定带日期和理由**，推翻时写清楚改了什么、为什么（比如「按状态排序会让行跳动，所以固定顺序」）。我们的 DESIGN 已经在这样做。
- i18n 从第一天就有（zh-CN + en）。

## 8. 以后借鉴（需要重新设计）

下面这些这一轮不做，但以后要借鉴，并按 CrossAgents 的模型重新设计：

- 多主机（SSH 配对、按主机分组、同时显示多台）、设备权限、多用户。
- 内置浏览器（可以借给 agent 用）、插件沙箱（opaque frame）。
- 完整的输入框：`Composer.tsx` 1466 行、队列面板按回合分组、拖动排序、停止后暂停的各种规则。这一轮先做最常用的路径，结构上给它留位置。

暂不考虑：Job Service、CC Switch 导入、模块开关和「放在哪里」的可配置项。

## 9. 建议的落地顺序

| 优先级 | 内容 | 主要改动 |
|---|---|---|
| P0 | 任务状态表（符号 + 词 + 分组），GUI 和 CLI 共用 | DESIGN 加表；`api-types` 导出状态到分组的映射 |
| P0 | Planner 对话里的任务卡片（一行，展开看规格 / 进度 / 提问 / 结果 / 操作） | GUI；hub 给 transcript 标出哪些 tool call 对应哪个任务 |
| P0 | engine / Worker 消息的紧凑行，人的消息才是右侧气泡 | `agent.input` 需要带发送方 |
| P0 | 按可折叠 / 不可折叠分串折叠，底部显示本轮状态 | `session.ts` 和 Rust 版的折叠逻辑 |
